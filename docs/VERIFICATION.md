# Verification and current limits

Automated checks verify bounded behavior of the current source. They do not establish production security, real-world governance effectiveness, professional assurance or standards conformity.

## Coverage

The complete application suite contains 143 tests across persistence, HTTP transport, native domain behavior and browser-controller checks. It uses isolated stores and fake provider adapters. A clean source-copy run is the test of whether the selected source distribution is complete; it needs no old design archive, private reference bodies or saved operator database.

| Check family | What it supports |
| --- | --- |
| Workspace / activity | Transactional saves, stable receipts, revision conflicts, saved projections and history |
| Reviews / evidence | Typed target membership, exact source captures, duplicate/conflict guards and remove/restore behavior |
| Originals / authored documents | Exact bytes, immutable versions, idempotent retention, source budget, parser bounds and recovery |
| Reports | Frozen basis, retained PDF/page hashes, older-version retrieval and interrupted/failed generation |
| Conversations | Frozen context, output/source checks, stop/late-result handling and human draft separation |
| Identity / team | Isolated bootstrap, credentials/sessions, grants, assignment scopes, API refusal and reader compatibility |
| UI controllers | Editing/navigation/save/recovery with DOM doubles; these are not native-browser screenshots |
| Source layout | Independent seed/PDF identity and exact bytes for all 35 served asset URLs; no physical read from the old design directory |

The predecessor fixture manifests pin 13 exact historical modules. They verify that older readers refuse newer original/document-bearing workspaces before mutation. The UI CSS golden and runtime-contract.json are independent regression oracles, not generated expectations taken from the current implementation during a test.

Source relocation was additionally compared against copies of the saved development workspace: 16 tables with schema/typed rows/BLOBs, seven read projections and three retained PDFs remained unchanged. These checks support that specific refactor and saved snapshot; they do not prove universal migration compatibility.

## Limits that remain

- The running application is single operator. Isolated identity/role tests do not connect team actors to native governance history or prove every source, binary, job and route is authorized for team use.
- The source runs a bounded fictional path, with deterministic document preparation and a focused PDF template. Pure modules for wider suite records do not mean every workflow is exposed or complete in the current app.
- Optional AI is a narrow cloud-backed draft task. Chat checks that cited sources were read; the older fixed Prepare action only checks allowed source IDs and a task read. Structural guards and earlier bounded trials do not validate arbitrary model output semantics or admit company data.
- Exact served bytes and DOM doubles support unchanged behavior/appearance inputs. Native painted layout, focus, scrolling, responsiveness and accessibility require rendered/manual verification under a declared environment. No complete native visual comparison is claimed.
- Full PDF/preview tests depend on the current Windows runtime, bundled paths/fonts and two workstation-specific Python test references. Packaging and portability remain unfinished.
- Parser bounds are not malware scanning; local request guards are not a production security assessment. Recovery tests are not an operational disaster-recovery qualification.
- No test or document declares compliance, certification readiness, risk acceptance or an authorized deployment.

## Next implementation boundary

Before connecting team work, complete authenticated actor attribution and compatibility for native saves/history, then enforce the full object/source/artifact access scope and bind the reviewed team UI. Preserve existing solo/external records. That work needs a reviewed connection design and meaningful end-to-end tests; do not enable team mode on the current database as a shortcut.

Run commands and dependency limitations belong in [Setup](SETUP.md). Record the exact source/environment and observed results when making a new verification claim. A passing local run is evidence for that candidate, not a release authorization.
